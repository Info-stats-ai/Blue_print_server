The Agent Panel

The Agent Panel gives you longer-running AI threads, separate from the I-mode panel. Press Cmd+? to open it.

When to use which

UseFor
I-mode panelQuick requests alongside team chat.
Agent PanelBigger tasks, separate threads, and tasks started from the task board.

Your two AIs

You have two AIs, and both can edit files and run commands: the Agent Panel on the left, and My AI in the I-mode panel on the right. Choose how they work in the people menu, under Your two AIs. The choice applies on its own or in a session, signed in or not.

ChoiceWhat happens
Work together (default)Each AI knows what the other was asked, what it's doing now and what it changed, so one builds on the other's work instead of redoing or undoing it. While the Agent Panel works, the I-mode panel shows its latest step, such as Agent panel: Edit src/tasks.rs.
Work separatelyNeither AI sees what the other does. Use it to try two approaches side by side.

Either way, the two never edit the same function at the same moment: function claims apply to both. What reaches your team is still set by your sharing level.

Use it with your team

Agent Panel threads are private to you, and they still work with your team:

  • An agent can check what your team is doing when your request needs it, using its team_context tool.
  • It follows the same function claims as other agents.
  • The files it changes go to your team when they're saved, if your sync is on Auto (see Syncing and merging).

Other agents

The welcome page and Agent Panel let you install other agents, such as Claude Agent, Codex, GitHub Copilot and Cursor. Each uses its own account or key.

Control what agents can do

Use tool_permissions in your settings to allow, block or always confirm actions:

{
  "agent": {
    "tool_permissions": {
      "tools": {
        "terminal": {
          "default": "confirm",
          "always_allow": [{ "pattern": "^pytest" }]
        }
      }
    }
  }
}

Connect outside tools

Add Model Context Protocol (MCP) servers to give agents more tools:

{
  "context_servers": {
    "my-server": {
      "command": "some-command",
      "args": []
    }
  }
}
