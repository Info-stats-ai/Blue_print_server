Team activity

Team activity is its own panel, next to your file folder. It shows who's here, the tasks, and where every file stands between you and the team.

It opens by itself when you start or join a session. Its button in the status bar shows or hides it, and you can drag the line between it and the file folder to resize it.

People and tasks

People lists who is present and which file and line each person is on. A colored label shows what they're doing: amber for editing, blue for agent running, grey for idle. Tasks come from a plan someone shared; each has an owner and a status. See Tasks.

Sync: Auto or Manual

The switch at the top of Files decides how files move. A new session starts on Auto, and you can change it at any time; your choice is remembered.

ModeWhat happens
AutoYour saves go to the team, and teammates' changes arrive on their own and merge with your work. Every AI sees a change as soon as it's saved.
ManualNothing leaves your machine until you press the sync button on a file, or Sync all. Teammates' changes wait for you. Their AIs wait for what you haven't sent.

On Manual, when several teammates' files are waiting for you, Take all adds them in one go. Files with your own changes aren't touched.

The gear next to the switch holds the finer choices: what teammates see of your AI's work, private paths, and a pause.

Merging and conflicts

When you and a teammate changed different parts of a file, the two versions merge on their own. If you each added a different function, both are kept.

When you both changed the same lines, nothing is merged silently. The file is marked conflict for everyone in the session, with both names, until the person holding both versions picks one or merges them.

Breaking changes

When a teammate's change renames a function, changes what it takes, or removes it, I-IDE checks your own code, including work you haven't sent, for calls to it. If it finds any, a Breaking changes card shows who changed what, the old and new version, and the lines that call it.

Select Ask AI to fix and your AI updates those calls for you, leaving your teammate's file alone. Your AIs are also told about open breaking changes, so new code uses the new version. Changes inside a function, or to its formatting, don't count, and neither do calls that still fit the new version: renaming a parameter you pass by position, or adding one with a default, doesn't break your call. A call I-IDE can't read for sure (it runs over several lines, or spreads its arguments) is listed, to be safe.

Your change breaks callers

The same check runs the other way. When you, or your AI, change or remove a function that code elsewhere calls, including teammates' synced code, a Your change breaks callers card lists the places, and who wrote them. It shows before you sync on Manual, and as you save on Auto. Select Fix the calls too and your AI updates them in the same piece of work, so teammates never hit the break. Your AI is told as well, so an agent that changes a function fixes its callers without being asked. The card clears as the calls are fixed.

Changes on the way

When a teammate's AI changes what a function takes, everyone in the session hears about it straight away, before the file is synced. Changes on the way shows the old and new version and, if your code calls it, where. Your AI is told too, so new code is written against the new version.

While their AI is still working on the task, that file waits: it reaches you when the task ends, together with the AI's fixes to the code that calls it, instead of half-finished. That's also your window to step in.

Select Hold on to ask their AI to stop. Their AI is told, and the file stays unsent until its owner syncs it. Select X if the change is fine by you.

Tests after changes

When you save, when your AI edits a file, and when a teammate's change lands in your copy, I-IDE runs the tests that use what changed, on your machine, and shows the result in Team activity: passed, or failed with the lines that explain why and Ask AI to fix. Only those test files run, so it takes seconds. It works with Python (pytest or unittest), Go, and JavaScript or TypeScript with Vitest or Jest. A newer run of the same tests replaces the older result. Switch it off under AI & sharing… → When code changes.

Discussion summary

When a session's chat gets long, an AI keeps a short summary of it: the goal, the decisions, who's doing what and the open questions. It's marked written by AI, and every AI is told it can be wrong and that pinned decisions and the code come first. If it gets something wrong, select the warning triangle and say what. Nobody's AI is given the summary until it has been rewritten with your correction. See Flag something as wrong.

Versions, without git

Every version of a file that reaches the team is kept, with who made it and when. Select the clock on a file to list them. View opens the file with what changed since that version marked. Restore puts that version back; it then counts as your newest change.

Git keeps working as usual if your project uses it. See Git.
