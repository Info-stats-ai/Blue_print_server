Git

Git is optional in I-IDE. A session syncs, merges and keeps file versions by itself, so a team can work together without it. If your project is a Git repository, everything here works as usual.

Open the Git panel

Press Ctrl+Shift+G. The panel lists changed files and lets you stage and commit them.

Commit a change

  1. Open the Git panel.
  2. Select the files to stage.
  3. Enter a commit message.
  4. Commit, then push.

See who changed a line

Press Cmd+Alt+G then B to turn on Git blame for the current file.

Git and team sessions

A session keeps its own versions of every synced file, separate from your commit history; see Syncing and merging. If you also commit, agree who commits what. A task board with one owner per task makes this easier.

Teammates on different branches

I-IDE knows which git branch each person is on, and keeps branches apart:

  • Same branch: files sync live, as usual.
  • Different branches: files never cross. A teammate's change on another branch reaches you as context: Team activity and your AIs hear what changed, but your files stay as they are.
  • Cross-branch radar: if their change will break your code once their branch is merged, a card lists the calls, before anyone merges.
  • Merge forecast: if you and they changed the same lines, a card says the file will conflict when the branches merge. It uses git's merge base, so it's a real forecast, not a guess.
  • Plan the merge: your AI plans how to merge in Plan mode. It reads, it doesn't change files.

Switching branch (in a terminal or the Git panel) is noticed within seconds, and what the app knew about the old branch's files is dropped, so a switch can never bring one branch's code into another. Version history is kept per branch.

It's your choice: in Team activity, or AI & sharing… → Teammates on other branches, turn sharing across branches off. Then only people on your branch see your changes, in both directions. Without git, everyone shares one copy, as before.
